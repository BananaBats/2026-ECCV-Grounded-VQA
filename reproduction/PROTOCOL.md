# Reproducing the experiments

## Perception Test validation

From the package root, `python -m reproduction.replay --output-dir outputs/val200` writes the score summary and both recomputed curves. It uses the saved model outputs and a local HOTA evaluator. All scores are question-macro averages on a 0–100 scale. The 200 questions served as a development set. [Evaluator source](benchmarks/postprocess/metrics/perception_eval.py)

**Cohort.** The selector orders all 3,051 validation questions by video ID and numeric question ID, then groups them by answer count (one or multiple) and question area (physics, memory or abstraction). It allocates 200 slots proportionally by largest remainder and draws from the six strata in lexicographic order with `random.Random(0)`. The result includes 120 single-target and 80 multi-target questions. Run `python reproduction/select_val200.py` to check the shipped list byte for byte. To start from the official annotations, add `--annotations /path/to/grounded_question_valid.json`. [Ordered list](data/perception_val200.tsv) · [Selection code used in the experiment](benchmarks/datasets/make_subset.py)

**Extent and cost.** The ablation removes positive changes in width and height from the accepted Gemini–SAM3 residuals. It retains center shifts, size reductions, sparse fallback boxes and the Full arm’s output frames and gap endpoints. The Direct and dense baselines use their saved predictions on annotated frames. The sparse baseline linearly interpolates its 1-fps boxes. API costs use recorded token counts and the Standard rates used in the paper. [Extent control](benchmarks/postprocess/controls.py) · [Anonymized token ledger](data/usage_counts.jsonl.gz)

**Threshold and holdout.** In the shared sweep, both IoU gates range from 0 to 1 in increments of 0.001. The holdout sorts all queried Gemini frames, including empty responses, and alternately hides the odd and even positions. A frame is eligible if it has answer GT and a SAM3 prediction with earlier and later same-ID SAM3/Gemini observations among the retained frames. Eligibility is fixed before the residual threshold varies. On the union of eligible frames, every arm scores the same SAM3 support once per question. Gap filling and sparse fallback are disabled for this diagnostic. The paired 95% intervals resample videos 5,000 times with seed 20261119. [Analysis code](analysis.py) · [Archived shared curve](reference/shared_tau_full_curve.csv) · [Archived holdout curve](reference/residual_holdout_full_curve.csv)

**Coordinates and inputs.** In the validation cache, `sam3` and `gemini` are keyed by target ID and original frame, with YXYX boxes on a 0–1000 scale. The historical dense exporter retained the global non-empty frame list and per-target visibility windows. The cache uses the same reconstruction of sampled boxes as the original scorer. Evaluation labels and final predictions use normalized XYXY. The frame maps include planning-proxy labels, anchor indices, SAM3 input frames and every Gemini query timestamp. The dataset credits and license are in the main README. [Validation inputs](data/val200.json.gz) · [Validation frame maps](data/val200_frame_maps.json.gz) · [Original input digests](data/val200_input_sha256.json)

## Benchmark settings and evaluation

| Reported split | Queries | Model | Fusion and box convention | Evaluation |
| --- | ---: | --- | --- | --- |
| Perception validation | 200 | Gemini 3.7 Flash | Minimal, amodal sparse boxes | HOTA on annotated answer frames |
| Perception test | 1,859 | Gemini 3.7 Flash | Historical v13, amodal, two dense fallbacks | Official hidden-test HOTA |
| VidSTG declarative test | 4,610 | Gemini 3.8 Flash | Minimal, visible sparse boxes, 85 dense fallbacks | TubeDETR 5 fps, at most 200 evaluation frames |
| HC-STVG v1 test / v2 validation | 1,160 / 2,000 | Gemini 3.8 Flash | Historical v13, amodal sparse person boxes | Native frames, predicted grounding interval |
| SVAG-Bench test | 1,833 | Gemini 3.7 Flash | Minimal, amodal, per-ID action intervals | Official SVAGEval, revision `65b1495` |

The profile registry identifies the implementation and archived evidence behind each reported row. Minimal uses two overlap checks at 0.30. Historical v13 adds track-level reliability checks and a short-gap rule. The 66.20 Perception test HOTA is the historical server result. Re-scoring the two official test submissions requires access to the corresponding ground truth or evaluation service. [Run registry](benchmarks/experiment_profiles.json) · [Cohorts and fallback IDs](benchmarks/configs) · [Generation settings](benchmarks/configs/generation.json)

**Frames.** Frame indices are zero-based on the input clip. For VidSTG and HC-STVG, add `clip_begin_fid` for source-video export. Each map lists its planning proxy, selected anchors, dense input grid and sparse observations. The Perception test dense grids are reconstructed from the saved plans with stride 3, the anchors, the final frame and the 15-frame visibility-boundary windows. The other five splits use archived SAM3 input maps. On fallback rows, an empty `gemini` list denotes that fusion used the dense export. [Benchmark frame maps](benchmarks/frame_maps) · [Temporal tube exporter](benchmarks/postprocess/legacy/stvg_export.py)

**Prompts and schemas.** The original Perception planner used object-only instructions. HC-STVG identifies the described person and predicts a grounding interval. VidSTG selects the referred entity. SVAG selects each instance performing the requested action. The planner dispatches both noun selection and verification using the selected profile. The archived modules contain the full prompt builders and response schemas. [Profile dispatch](benchmarks/pipeline/plan.py) · [HC-STVG person prompts](benchmarks/pipeline/_legacy/hcstvg/hcstvg_prompts.py) · [Archived model code](benchmarks/pipeline/_legacy)

**Other benchmark inputs.** With the corresponding dataset, the adapters prepare GT-free query manifests and separate evaluation annotations. From `reproduction/benchmarks`, run `python -m postprocess.evaluate stvg --help` for the tube scorer, `python -m postprocess.evaluate export-stvg --help` for clip-to-source export, or `python -m postprocess.evaluate svagzip --help` for the official submission format. Select `hc_native` for HC-STVG and `vidstg_5fps_max200` for the reported VidSTG row. The SVAGEval source archive includes its spatial and temporal scorers and licenses. [Dataset adapters](benchmarks/datasets) · [SVAG input adapter](benchmarks/pipeline/prepare_svag.py) · [SVAGEval source](benchmarks/SVAGEval-65b1495.tar.gz) · [Upstream revision](https://github.com/Shuaicong97/SVAGEval/tree/65b14956083db0541917cf92c2ceca3b11c09ee2)

The portable benchmark modules retain the experiment code and replace machine-specific paths with caller-supplied paths. The source manifest distinguishes the original file hashes from hashes of the delivered files. Run `shasum -a 256 -c SHA256SUMS` from the package root to check the extracted copy.
